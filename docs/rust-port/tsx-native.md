# TS 应用的原生模块（Rust 版，WP-5.8）

Zig 版的规范见 `docs/tsx-native.md`。Rust 版把「Zig 编译期检查 `native/<名字>.zig` 与
`native/<名字>.ts` 一致」换成「`zant-tsx` 从 `.ts` 规范生成 Rust trait，应用写 `impl`，
签名不符由 rustc 报错」；TSX 调用仍是**直接调用**（无桥接、无序列化），只是目标从
Zig 函数变成 trait 的关联函数。

```
my-app/
  src/                  只有 TS/TSX
    App.tsx             import { copy, entries } from "native/clips";
  native/
    lib.rs              模块清单：pub mod clips;
    clips.ts            规范（唯一来源）
    clips.rs            实现：pub struct Native; impl ClipSpec for Native { … }
    engine/…            内部代码（子目录不会被当成规范）
```

`zant-tsx` 把项目里所有 `native/*.ts`（不含 `.d.ts`、不含子目录）编译成一个生成文件
`native/spec.rs`（对应 Zig 版的 `spec.zig` + 每个 `_spec_<名字>.zig`）：

```rust
// @generated by zant-tsx from native/*.ts (the native module specs) - do not edit.

/// The spec `native/clips.ts`: `native/clips.rs` implements the trait below.
#[allow(dead_code)]
pub mod clips {
    use zant::tsx;

    #[derive(Clone, PartialEq, Default)]
    pub struct ListEntry {
        pub row: i64,
        pub kind: super::kinds::Kind,
        pub preview: zant::Str,
        pub from: Option<zant::Str>,
    }

    #[derive(Clone, Copy, Default, PartialEq, Eq)]
    pub enum CopyResult { #[default] Ok, NotFound }

    pub trait ClipsSpec {
        fn entries(query: zant::Str) -> tsx::List<ListEntry>;
        fn copy(row: i64) -> CopyResult;
        fn clear();
    }

    pub const NAME: &str = "clips";
}

/// The spec `native/kinds.ts`: types shared with other specs.
#[allow(dead_code)]
pub mod kinds {
    /* … Kind 枚举 … */
}
```

规则：

- 每个 `export declare function` → `pub trait <名字>Spec` 的一个关联函数（没有 `self`，
  与 Zig 的自由函数一致）；`void` 返回省略 `-> ()`。
- `NAME` 是该 spec 的注册键（见下）；**没有** `export declare function` 的纯类型规范
  （上面 `kinds`）只生成类型，不生成空的 trait 和 `NAME`——它没有需要实现的函数。
- spec 之间共享类型：`import type { Kind } from "./kinds"` 在生成代码里写成
  `super::kinds::Kind`；应用里则写 `crate::native::spec::kinds::Kind`。
- 每个 `interface` / 命名对象 / 字符串联合都生成 `#[derive(Clone, PartialEq, Default)]`
  的 struct / enum（与 `docs/rust-port/tsx-codegen.md` §2 相同）；`export type X = T[]`
  这类别名生成 `pub type X = tsx::List<T>;`，保证别的 spec 能按名字引用它。

## 应用实现：`native/clips.rs`

```rust
use crate::native::spec::clips::{ClipSpec, CopyResult, ListEntry};
use zant::tsx;

pub struct Native;

impl ClipSpec for Native {
    fn entries(query: zant::Str) -> tsx::List<ListEntry> { /* … */ }
    fn copy(row: i64) -> CopyResult { /* … */ }
    fn clear() { /* … */ }
}
```

缺函数、参数或返回类型不符、把 `fn` 写成 `&self` 方法，都是 `impl` 处的 rustc 错误
（Zig 版是 `native/clips.zig: missing …` / `is … but native/clips.ts declares …` 的编译错误）。
实现里可以有规范之外的 `pub fn`，它们只给 Rust 自己用。

`native/lib.rs` 由应用写，列出实现模块（对应 Zig 版 `native/lib.zig`）：

```rust
pub mod clips;
```

## 注册（可选）

生成的入口在启动时注册一次，键是生成的 `NAME`（WP-5.6 生成这段代码）：

```rust
zant::tsx::native::register_named(
    crate::native::spec::clips::NAME,
    crate::native::clips::Native,
);
```

`zant::tsx::native` 提供 `register_named` / `get_named::<T>`（新加的按名字注册，
供生成的 spec 用）、`register` / `get::<T>`（`NativeModule` 关联常量 `NAME` 的手写形态）、
`registered` / `clear`。生成的调用点（下面的 `<Native as ClipSpec>::entries(..)`）**不经过**
注册表；注册表只用于按名字查找（`invoke` 命名空间、测试替换实现、运行时按名字挂模块）。

## TSX 里调用（WP-5.6 生成）

```tsx
import { entries, copy, type ListEntry } from "native/clips";

const list: ListEntry[] = entries(query);
<Button onClick={() => copy(entry.row)}>复制</Button>
```

生成：

```rust
use crate::native::spec::clips::{ClipSpec, ListEntry};
use crate::native::clips::Native;
use zant::tsx;

let list: tsx::List<ListEntry> = <Native as ClipSpec>::entries(query.clone());
// copy(entry.row):
<Native as ClipSpec>::copy(entry.row);
// 类型标注：entry 是 crate::native::spec::clips::ListEntry
```

- 规范里导入了不存在的名字 / 从 `native/<不存在>` 导入，报错在 `.tsx` 的那一行：

  ```
  native/clips.ts declares no exported `paste`
  cannot find `native/files`: add native/files.ts (the spec) and native/files.rs
  ```
- 类型导入（`import { type ListEntry }`）只在生成代码里变成
  `crate::native::spec::clips::ListEntry`，不产生运行时开销。

## 类型映射

与 `docs/rust-port/tsx-codegen.md` §2 相同：

| 规范 | Rust |
|---|---|
| `string` | `zant::Str`（字面量 `"…".into()`，运行时 `Str::copy(..)`） |
| `number` | `f64`（上下文是整数类型时按上下文） |
| `boolean` | `bool` |
| `i64` / `u32` 等（`import type { … } from "zant"`） | 同名整数 |
| `T[]` | `tsx::List<T>` |
| `T \| null` / `T \| undefined` | `Option<T>` |
| 可选参数 `x?: T` | `Option<T>` 参数（调用方传 `None`） |
| `"a" \| "b"` | `#[derive(Clone, Copy, Default, PartialEq, Eq)] pub enum` + `as_str()` |
| `interface` / 命名对象类型 | `#[derive(Clone, PartialEq, Default)] pub struct` |
| `void` | 返回 `()`（trait 里省略返回类型） |

规范里不能有：函数体、常量、回调类型、内联对象 / 联合（必须用
`export type Name = …` / `export interface Name` 命名）、`Map` / `Set` 等不支持的类型。
诊断文字与 Zig 版相同（只把 `.zig` 换成 `.rs`），例如：

```
native/clips.ts:2:1: error: a spec declares functions (`export declare function copy(…): …;`); write them in native/clips.rs
native/clips.ts:1:60: error: name an object type the Rust side uses: `export type Name = …;` / `export interface Name { … }`
```

## 生成器接口（WP-5.6 / `compile.rs` / `entry.rs` 调用）

`crates/zant-tsx/src/native_specs.rs`：

| 函数 | 用途 |
|---|---|
| `module_name(source)` | `"native/clips"` → `Some("clips")`；识别 `.tsx` 里的 native 导入 |
| `Spec { name, module }` / `find` / `spec_for` | 项目 spec 列表、按名字查找、找不到时给出「add native/…」诊断 |
| `import(spec, ImportName, type_only)` | 把一个导入名分类为 `Type` / `Function`，并给出与 Zig 相同的诊断 |
| `exported_type(module, name)` / `declared(module, name)` | 取规范导出的类型 / 声明函数（5.6 解析导入类型时用） |
| `validate(g, module, name)` | 规范的结构检查（诊断同 Zig） |
| `generate(module, name, specs, diag)` | 一个 spec 的 `pub mod <名字> { … }` |
| `spec_root(specs, diag)` | 整个 `native/spec.rs`：固定文件头 + 按名字排序的 spec 模块；输出先用 `syn::parse_file` 校验 |
| `has_functions(module)` | 该 spec 是否生成 trait（入口只给这些 spec 生成注册代码） |
| `trait_name(name)` / `module_ident(name)` | `clips` → `ClipsSpec` / `clips`（生成路径用） |
| `app_spec_path` / `app_trait_path` / `app_impl_path` / `app_type_path` | 生成代码里的路径：`crate::native::spec::clips`、`…::clips::ClipsSpec`、`crate::native::clips::Native`、`…::clips::ListEntry` |

`native/spec.rs` 的模块路径固定为 `crate::native::spec::<module_ident>`，
实现模块固定为 `crate::native::<module_ident>`；`native/lib.rs`（模块清单）与
`native/spec.rs` 的写入由 WP-5.6 的 `compile` / `entry` 接。

## 与 Zig 版的差异

1. 检查机制：Zig 的 `src/tsx_native.zig`（`@hasDecl` / `@TypeOf` 的 comptime 检查）删除，
   改为生成 trait + `impl` → rustc 报错；`native/lib.rs` 的模块清单仍由应用写。
2. 生成布局：一个 `native/spec.rs` 里每个 spec 一个 `pub mod`（Zig 是 `spec.zig` 根 +
   `_spec_<名字>.zig` 多文件）；spec 之间的类型引用因此是 `super::<名字>::<类型>`。
3. 纯类型规范不再需要空实现模块（Zig 的 `check(comptime Impl)` 会要求 `native/kinds.zig`
   存在）；它们没有 trait / `NAME`，入口也不为它们生成注册代码。
4. 参数类型：Zig 的 `[]const u8` 参数在生成 trait 里是 `zant::Str`（按 §2 的 `string` 映射；
   `Str` 是廉价克隆的不可变字符串）。
5. 注册表：Zig 的检查是纯编译期、没有运行时注册表；Rust 保留一个可选的按名字注册表
   （`zant::tsx::native`，WP-5.7），生成的静态调用不走它。
