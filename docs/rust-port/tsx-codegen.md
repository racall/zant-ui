# TSX → Rust 代码生成设计（WP-5.1）

> 负责人产出，WP-5.2–5.10 照此实现。契约见 [api.md](api.md) 与 plan.md §4；前端（M4）把
> `.tsx` 变成 AST，本文规定 AST → Rust 源码的**全部规则**。执行中发现规则不成立，
> 登记 `status.md` 的「待决问题」，不要自行改规则。

## 1. 流水线

```
src/App.tsx ──lexer/parser（WP-4.1/4.2）──▶ ast::Program
            ──hooks 展开（WP-4.3）───────▶ ast::Program（无自定义 hook）
            ──codegen（WP-5.3..5.6）──────▶ Rust 源码（String）
            ──syn::parse_file + prettyplease（校验 + 格式化）
            ──zant-build 写 OUT_DIR/generated.rs，应用 main.rs `include!`
```

- 编译期完成，**没有 JS 运行时**。一个 `.tsx` 文件 → 一个 Rust 模块。
- 输出必须能被 `syn::parse_file` 解析；失败即 `panic!` 并打印生成的源码（含 TSX 位置）。
- 生成文件头固定：

```rust
// @generated by zant-tsx from src/App.tsx — do not edit.
#![allow(clippy::redundant_clone)]
#![allow(clippy::too_many_arguments)]
```

## 2. 类型映射

| TSX | Rust | 说明 |
|---|---|---|
| `string` / 模板字面量 | `zant::Str` | 字面量 `"...".into()`（`Static`，零分配）；运行时拼接用 `Str::copy(&format!(..))` |
| `number`（默认） | `f64`；赋给 `u8..i64/usize/f32` 上下文时按上下文类型 | TS 数值只有一种类型；推断不出上下文时默认 `f64` |
| `boolean` | `bool` | |
| `T[]` / `Array<T>` | `tsx::List<T>` | `Rc<Vec<T>>`，写时复制；`Some` 变体：`List::push(&mut self, ..)` 内部 `Rc::make_mut` |
| `T | null` / `T | undefined` | `Option<T>` | `?.`、`??`、`if (x != null)` 做 narrowing |
| 联合字面量 `"a" | "b"` | `enum { A, B }` | 变体名：kebab/空格 → PascalCase；`as_str()` 生成原字面量 |
| `interface` / 对象字面量类型 | `#[derive(Clone, PartialEq, Default)] pub struct` | 字段按声明顺序；全部 `pub` |
| 函数类型（props 回调） | `Rc<dyn Fn(..)>`；驱动状态的回调走 `ui::Action` | 见 §5 |
| `Map` / `Set` / 其它 | **不支持**，报诊断 | 需要就登记待决问题 |
| `any` | `zant::tsx::Any`（`enum` 包装 `Str/f64/bool`） | 仅用于 `console.log`/动态属性等边角 |

`interface` 名冲突（两个文件同名）由 `imports` 规则加模块前缀消解。

## 3. 所有权规则（**最重要**）

1. **TSX 的值要么 `Copy`，要么廉价 `Clone`**：`Str`、`List<T>`、`Rc<..>`、`u8..f64/bool`、
   派生 `Clone` 的 interface 结构体。
2. **每次读取非 `Copy` 变量都生成 `.clone()`**，不做「最后一次使用」优化，不生成借用。
   codegen 因此**不需要借用分析**，永远不会产生借用检查错误。
3. 生成函数的参数里的 `&mut self` 字段读取同理：`self.name.clone()`。
4. 状态字段原地更新：`let count: u32 = self.count;` 然后 `self.count = count + step;`
   （TS 的 `count = count + step`）。若表达式里多次读同一字段，codegen 先 `let` 出来。
5. 写时复制容器（`List<T>`）`push`/`splice` 等用 `Rc::make_mut`，语义同 TS 数组修改。

## 4. 值表示与优先级

沿用 Zig 版的 `types.Value { ty: Type, code: String, precedence: u8 }`：

- `code` 现在是 Rust 表达式源码。
- `precedence` 用 Rust 运算符优先级表（`|`=5 … 赋值=0；primary=20）。父表达式需要时加括号，
  规则与 Zig 版一致（`prec < parent_prec` 时包括号）。
- `zig_text.zig` → `rust_text.rs`：标识符转义、字符串字面量（`b"..."` 不需要；所有字面量走 `Str`）、
  数字字面量（`1` / `1.0` / 后缀按目标类型）。

## 5. 事件与 props

JSX 属性 → 选项结构体字段，**一一对应**（由 `#[derive(TsxProps)]` 在编译期生成的清单驱动，
见 WP-5.2 的 `zant-tsx-tags`）：

```tsx
<Button text="Reset" on_click={() => setCount(0)} disabled={count === 0} />
```

```rust
ui::button(ui::ButtonOptions {
    text: "Reset".into(),
    on_click: Some(ui::action(|s: &mut Counter| s._on_click1())),
    disabled: count == 0,
    ..Default::default()
})
```

- `on_click={...}` → 生成私有方法 `fn _on_click_<n>(&mut self)`，包里写内联函数体（TS 的箭头函数
  直接成为方法体：`setCount(0)` → `self.count = 0;`）；同一个 prop 的多次出现递增编号稳定命名。
- 事件 prop 需要参数时（`on_change`/`on_select`/`on_pointer`）：生成
  `ui::text_action(|s: &mut C, v: &str| ...)` / `ui::bool_action` / `ui::index_action` /
  `ui::range_action` / `ui::pointer_action`，函数体里把 event 参数映射为局部变量。
- `key={...}` → `key: Some(Str::copy(&..))`。
- 已绑定的子节点：`children: nodes![a, b]`。

## 6. 组件与状态

### 6.1 根组件（每个 TSX 应用一个）

```rust
#[derive(Default)]
pub struct App { count: u32, name: Str, notify: bool }

impl zant::ui::App for App {           // App trait 见 api.md §应用入口
    fn render(&mut self) -> ui::Node { .. }   // TSX 的 return (...) 生成在这里
}
```

- `useState` 的初始值 → 字段 + `Default`/`new()` 初值。
- `useRef` → 字段（`Rc<RefCell<T>>` 仅在跨闭包共享时）。
- `useMemo` → 字段 + render 里 `if self._memo_x.is_none() { .. }`（或 `ui::memo` 持有）。
- `useEffect` → `ui::effect(ui::action(|s: &mut App| ..))`，依赖数组决定是否每帧入队。
- `useReducer` → 字段 + `fn dispatch(&mut self, action: ..)`。

### 6.2 子组件（`function Child(props: Props)`）

```rust
pub fn build(props: Props, id: u64) -> ui::Node {
    let state: Rc<RefCell<ChildState>> = ui::local_state::<ChildState>(id, ChildState::default);
    // 回调捕获 state.clone()
    ui::column(ui::BoxOptions { .. })
}
impl ChildState {
    fn increment(&mut self) { .. }
}
```

- 调用点 id：`tsx::child_id(parent_id, "Child", key)`（有 key）／`tsx::site_id(parent_id, "Child", n)`（无 key，
  n 是源码位置序），算法照搬 Zig（Wyhash），**必须与 Zig 版结果相同**（已有 `core::hash` 移植）。
- 子组件的局部状态（useState 等）全部放进 `local_state` 的 `Rc<RefCell<T>>`；`Action::new(move |_| ..)`
  捕获它，不依赖根状态。

### 6.3 `App` 的生命周期钩子

`on_start` / `on_wake` / `on_close_request` / `on_quit_request` / `on_app_event` / `on_exit` 在 TSX
里声明为方法时，生成 `impl zant::ui::App` 的对应默认方法；`windows` / `desktop` 钩子（WP-5.6）生成
`RunOptions`/`Windows` 配置。

## 7. 语句与表达式

- 变量声明：`let x: T = ..;`；块作用域照 TS（Rust 块语义相同）。
- `if/else`、`while`、`for (const x of arr)`（→ `for x in arr.iter().cloned()`）、
  `for (let i = 0; i < n; i++)`、`switch`（→ `match`，fallthrough 报诊断）、`try/catch`（→ 不支持，诊断）。
- 逻辑：`&&` / `||` / `!` → Rust 同名（`&&`/`||` 短路语义相同）；`??` → `unwrap_or` / `unwrap_or_else`。
- 三元 `a ? b : c` → `if a { b } else { c }`。
- 比较 `===`/`!==` → `==`/`!=`（两边都是 `PartialEq` 类型）。
- 字符串拼接：`a + b` → `Str::copy(&format!("{}{}", a, b))`（TS 里 + 一侧是字符串即拼接）。
- 数组字面量 → `tsx::List::from_vec(vec![..])`；数组方法映射表见 `array_methods.rs`（§8）。
- `console.log(..)` → `zant::tsx::builtins::log(..)`（写 stderr，调试用）。

## 8. 内建与 JS 语义（`tsx_builtins`）

| TS | Rust |
|---|---|
| `Math.floor/ceil/round/abs/min/max/pow/sqrt/random` | `f64` 同名 + JS 取整语义（`Math.round(-0.5) == -0`） |
| `Number(x)` / `parseInt` / `parseFloat` / `isNaN` / `isFinite` | `tsx::builtins::number/parse_int/..`（JS 规则，非 Rust `FromStr`） |
| `String(x)` / `.toString()` / `.toUpperCase()` / `.toLowerCase()` / `.trim()` / `.split()` / `.slice()` / `.includes()` / `.startsWith()` / `.endsWith()` / `.replace()` / `.repeat()` / `.padStart()` / `.padEnd()` | `tsx::strings`（JS 码点语义、负索引、UTF-16 长度） |
| `JSON.stringify/parse` | `serde_json`（字段顺序按 struct） |
| `Date.now()` / `setTimeout` / `setInterval` / `requestAnimationFrame` | `tsx::timers`（`ui::wake_after`，单线程调度） |
| 数组：`map/filter/reduce/forEach/find/findIndex/some/every/push/pop/shift/unshift/splice/slice/indexOf/includes/join/sort/reverse/length` | `array_methods.rs`，`map`→`map`/`collect`，`sort` 用 JS 比较器语义（稳定） |
| `Promise` / `async` | **不支持**（阻塞调用放 native 模块），诊断 |

## 9. 模块、导入与 native

- `import { X } from "./X"` → 同项目组件：`use crate::x::X;`（模块名 = 文件 stem，冲突时加父目录）。
- `import { invoke } from "@/native/clip"`（native 模块，WP-5.8）→ `use crate::native::clip::Native;`
  `invoke::list()` → `<Native as ClipSpec>::list()`；应用在 `native/clip.rs` 里
  `impl ClipSpec for Native`，签名不符由 rustc 报错。
- `import { openFile } from "zant"` → `zant::dialogs::open_file()`；`"zant/desktop"` → `zant::desktop`。
- 第三方 npm 包 → 诊断（无 JS 生态；需要就在 native 模块里实现）。
- `zig_imports.zig` → `rust_imports.rs`：用 `syn` 读被导入 `.rs` 的 `pub fn` 签名，生成调用处的类型信息。

## 10. 黄金用例

- `tools/tsx/testdata/*.tsx` 的 32 个用例：期望输出从 `.zig` 换成 `.rs`，
  由新编译器生成后**人工逐个审阅**再签入（WP-5.9）。
- `tests/tsx/**`（多文件、hooks、native、windows）同样迁到 Rust 版并驱动运行期测试。
- 回归门槛：`bench-tsx` 中 TSX 生成代码不慢于手写 Rust 对照组 1.2 倍。
