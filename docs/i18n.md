# 多语言（i18n）

Zant 应用把界面文字放在 `locales/<语言>.json`，TSX 里用 `t("键")` 取当前语言的文字。
键和参数在**编译期**检查（写错键、漏参数、参数类型不对都是编译错误），运行时按数字 ID 查表，
没有 JS 运行时，也没有运行时 JSON 解析。用法与 react-i18next / react-intl 相近，不需要 Provider。
`zant create` 生成的项目默认英文（`locales/en.json`），并带一份 `zh-CN.json` 和语言切换示例。

```
my-app/
  locales/en.json        每种语言一个文件，文件名是 BCP-47 标签（en、zh-CN、zh-Hant、pt-BR…）
  locales/zh-CN.json
  zant.i18n.d.ts         zant 自动生成并维护的编辑器类型（键补全、参数检查），提交进仓库
  app.config.json        "i18n": { "default_locale": "en", "remember": true }
```

## 语言文件

平铺或嵌套都可以，嵌套键按 `.` 展平（`{"home": {"title": "Hi"}}` 等于 `{"home.title": "Hi"}`）：

```json
{
  "home": {
    "title": "Welcome, {name}",
    "items": "{count, plural, =0 {No items} one {# item} other {# items}}",
    "greeting": "{period, select, morning {Good morning} other {Hello}}"
  }
}
```

消息语法是 ICU MessageFormat 的子集（与 FormatJS / ICU4J 一致）：

| 写法 | 含义 |
| --- | --- |
| `{name}` | 参数原样显示；可传字符串或数字 |
| `{n, number}` | 数字参数 |
| `{n, plural, =0 {…} one {…} other {…}}` | 复数：先匹配 `=N`，再按该语言的 CLDR 规则选 `zero/one/two/few/many/other`；分支里 `#` 是数字 |
| `{x, select, a {…} other {…}}` | 按字符串选分支 |
| `''`、`'{…}'` | 单引号转义（ICU 的 DOUBLE_OPTIONAL 规则，`It's` 不需要转义）。单引号只在紧跟语法字符时开始转义：`{`、`}` 处处都是，`#` 只在 plural 分支里是（`'#'` 在那里输出 `#`，在顶层原样输出 `'#'`，与 ICU4J / FormatJS 一致） |

`plural` / `select` 必须有 `other`。尚不支持 `selectordinal`、日期 / 时间 / 货币格式、数字样式与
富文本标签（`<b>` 按普通文字显示），用到时会报编译错误。数字按 JS `String(n)` 显示（与模板字符串一致），
本地化的千分位分组随后续数字格式化提供。复数规则来自 CLDR 49（`crates/zant-base/data/cldr/`）。

规则：

- **默认语言**（`i18n.default_locale`；只有一个文件时就是它）定义所有键和参数。
- 其他语言不能有默认语言没有的键，也不能把参数用成默认语言没承诺的类型（例如默认是普通 `{n}`，
  译文用 `{n, plural, …}`）；可以省略参数。缺少的键是构建警告，运行时整条回退到默认语言
  （并用默认语言的复数规则）。
- `zant.` 开头的键保留给框架内置文案。
- 错误都带 `文件:行:列`，例如 JSON 写错、重复键、`"home"` 既是消息又是分组、ICU 语法错误。

## TSX API

```tsx
import { t, useLocale, setLocale, locales, localeName, localePreference } from "zant";

export function LanguagePicker() {
  const current = useLocale();
  return <Row gap={8}>
    {locales().map((tag) => (
      <Button variant={tag === current ? "primary" : "default"} onClick={() => { setLocale(tag); }}>
        {localeName(tag)}
      </Button>
    ))}
    <Button onClick={() => { setLocale("system"); }}>{t("settings.system")}</Button>
  </Row>;
}
```

| API | 说明 |
| --- | --- |
| `t(key)` / `t(key, { 参数 })` | 当前语言的文字。键是字符串字面量，或成员都是同参数键的字面量联合类型（`type Status = "status.open" \| "status.done"`）；参数用对象字面量 |
| `useLocale()` | 当前语言标签 |
| `setLocale(tag \| "system")` | 切换所有窗口并记住选择（`remember: false` 时不保存）；只能在事件 / effect 里调用；应用没有的语言返回 false |
| `localePreference()` | 用户的选择：标签或 `"system"` |
| `locales()` | 应用的语言列表（排序） |
| `localeName(tag)` | 语言自称（`简体中文`、`English`），用于语言选择器 |

`t` 是普通函数，组件、事件、普通函数里都能调用（顶层常量里不行：语言会变）。不要把翻译结果存进 state / store
等长期数据；存键和参数，渲染时再翻译。`useMemo` 缓存译文时把 `useLocale()` 放进依赖。

## 语言怎么选

启动时：用户上次的选择（保存在应用数据目录 `locale` 文件）→ 系统首选语言列表
（macOS 系统设置的语言顺序；Windows 显示语言列表）与应用语言协商 → 默认语言。
协商先找完全相同的标签，再找同语言同文字（`zh-Hans-CN` → `zh-CN`；`zh-TW` / `zh-HK` 是繁体，
不会落到简体），再同语言其他地区。切换后所有窗口立即重建；`ui::memo` 子树随之失效。
热刷新保留当前选择，改 `locales/*.json` 原地热刷新。

后台线程（如原生模块发请求带 `Accept-Language`）用 Rust 的 `zant::i18n::context::current_tag()`。

## 已知限制

- 原生窗口标题（`createWindow({ title })`、`app.config.json` 的 `title`）目前是静态的。
- macOS 系统提供的界面（打开 / 保存面板、系统菜单项）跟随系统语言，不跟随应用内切换。
- 「跟随系统」在启动和 `setLocale("system")` 时读取系统语言；运行中改系统语言，同 macOS / Windows 原生应用，重启应用后生效。
- CLDR 没有复数规则的语言（构建时警告）只用 `other` 分支。`t()` 找不到消息属于装配错误（目录没安装、或不是本次构建的目录）：打印一次警告，并显示键名而不是空白。
- 框架组件的内置文案（Markdown 复制按钮、PDF 阅读器工具栏等）默认英文，跟随应用语言的内置语言包与
  `zant.*` 覆盖在后续版本提供。
- 暂不支持从右到左（RTL）布局。

`crates/zant/src/i18n/`（CLDR 复数、语言协商、目录、格式化、当前语言）、`crates/zant-build/src/i18n.rs`、
`crates/zant-cli/src/declarations.rs`。
